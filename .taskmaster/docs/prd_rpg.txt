# Mider - Product Requirements Document (RPG Method)
## Version: 2026 Q1 | Repository Planning Graph Structure

---

## Problem Statement

Enterprise developers working with legacy codebases (C, SQL, XML) spend significant time understanding complex code structures, tracing call relationships, and making safe modifications. Existing tools either:
- Lack domain-specific understanding (generic IDEs)
- Require context switching between multiple tools
- Don't provide AI-assisted analysis tailored to enterprise patterns (IO Formatters, TrxCodes, DBIO)

**Pain Points:**
- New team members take weeks to understand legacy code structure
- Code reviews miss domain-specific patterns (Oracle hints, (+) joins)
- Manual tracing of TrxCode → C program → SQL relationships
- No unified tool for analyze → ask → edit → test workflow

## Target Users

**Primary: Enterprise Developers**
- Work with C programs, SQL procedures, XML UI definitions
- Need to understand legacy code quickly
- Make targeted modifications with confidence

**Secondary: System Administrators**
- Review code before deployment
- Need quick structural understanding
- Verify changes don't break dependencies

## Capability Tree

### Capability: Core Analysis Engine
Provides LLM-powered code structure analysis with file-type specialization.

#### Feature: File Type Detection
- **Description**: Automatically detect and categorize files by type (C, SQL, XML, generic)
- **Inputs**: File path, file content
- **Outputs**: FileType enum, confidence score
- **Behavior**: Check extension, validate content patterns, return categorization

#### Feature: C File Analysis
- **Description**: Analyze C files for IO Formatters, DBIO patterns, standard functions
- **Inputs**: C file content, analysis depth level
- **Outputs**: Structured analysis (functions, call graph, IO structures)
- **Behavior**: Parse functions (a000_init, b000_validation, c000_main, z999_error), extract DBIO calls, identify IO Formatter structures

#### Feature: SQL File Analysis
- **Description**: Analyze SQL files for Oracle-specific patterns
- **Inputs**: SQL file content
- **Outputs**: Bind variables, joins, hints, nullable info
- **Behavior**: Parse Oracle SQL, detect (+) joins, extract hints, identify date patterns (99991231)

#### Feature: XML File Analysis
- **Description**: Analyze XML UI files for TrxCode patterns
- **Inputs**: XML file content
- **Outputs**: TrxCodes, UI components, scwin.xxx functions, data flows
- **Behavior**: Parse XML structure, extract JavaScript functions, map data bindings

#### Feature: Repository Mapping
- **Description**: Generate lightweight repository structure maps
- **Inputs**: Directory path, priority rules
- **Outputs**: RepoMap with file relationships
- **Behavior**: Scan directories, prioritize by file type, cache results

### Capability: Interactive CLI Interface
Provides REPL-based interaction with rich UI formatting.

#### Feature: Command Parser
- **Description**: Parse and route user commands to appropriate handlers
- **Inputs**: User input string
- **Outputs**: Parsed command, arguments
- **Behavior**: Identify command prefix (/add, /ask, etc.), extract arguments, validate syntax

#### Feature: Mode Management
- **Description**: Switch between ASK and EDIT modes
- **Inputs**: Mode switch command
- **Outputs**: Mode state change
- **Behavior**: Update current mode, load appropriate prompts, notify UI

#### Feature: Rich UI Rendering
- **Description**: Display formatted output using Rich library
- **Inputs**: Content, display type (panel, table, tree)
- **Outputs**: Rendered terminal output
- **Behavior**: Format content, apply styling, handle terminal width

#### Feature: Auto-completion
- **Description**: Provide command and file path completion
- **Inputs**: Partial input, context
- **Outputs**: Completion suggestions
- **Behavior**: Match commands, scan file paths, rank suggestions

### Capability: Code Editing System
Provides three-strategy file editing with backup and rollback.

#### Feature: WholeFile Strategy
- **Description**: Replace entire file contents
- **Inputs**: File path, new content
- **Outputs**: Applied change, backup reference
- **Behavior**: Backup original, validate content, write new file

#### Feature: EditBlock Strategy
- **Description**: Replace specific code blocks
- **Inputs**: File path, block markers, new content
- **Outputs**: Applied change, affected lines
- **Behavior**: Locate block boundaries, preserve context, apply replacement

#### Feature: Udiff Strategy
- **Description**: Apply unified diff patches
- **Inputs**: File path, diff content
- **Outputs**: Patched file, conflict status
- **Behavior**: Parse diff, locate hunks, apply patches with conflict detection

#### Feature: Backup & Rollback
- **Description**: Maintain edit history with undo capability
- **Inputs**: File path, operation ID
- **Outputs**: Restored file state
- **Behavior**: Store timestamped backups, track operation chain, support rollback

### Capability: AI Orchestration
Provides multi-step task planning and execution.

#### Feature: Plan Generation
- **Description**: Generate execution plans from natural language requests
- **Inputs**: User request, context
- **Outputs**: ExecutionPlan with ordered steps
- **Behavior**: Analyze request, decompose into steps, assign commands

#### Feature: Plan Execution
- **Description**: Execute plans step-by-step with user approval
- **Inputs**: ExecutionPlan, approval mode
- **Outputs**: Execution results per step
- **Behavior**: Execute steps sequentially, handle failures, allow intervention

#### Feature: Plan Persistence
- **Description**: Save and restore execution plans
- **Inputs**: Plan state, file path
- **Outputs**: Serialized plan / restored state
- **Behavior**: Serialize to YAML, track completion state, enable resume

### Capability: Session Management
Provides session state persistence and restoration.

#### Feature: Session State Tracking
- **Description**: Track current session state (files, history, mode, cache)
- **Inputs**: State changes
- **Outputs**: Current session snapshot
- **Behavior**: Maintain in-memory state, track changes incrementally

#### Feature: Session Persistence
- **Description**: Save session to disk for later restoration
- **Inputs**: Session state, save path
- **Outputs**: Serialized session file
- **Behavior**: Serialize state to JSON, include timestamps, handle large contexts

#### Feature: Session Restoration
- **Description**: Restore previous session state
- **Inputs**: Session file path
- **Outputs**: Restored session state
- **Behavior**: Deserialize JSON, validate integrity, rebuild caches

### Capability: Performance Optimization
Provides caching and optimization for responsive experience.

#### Feature: Analysis Caching
- **Description**: Cache analysis results with file-hash keys
- **Inputs**: File path, analysis type
- **Outputs**: Cached result or cache miss
- **Behavior**: Hash file content, lookup cache, invalidate on change

#### Feature: Prompt Caching
- **Description**: Cache LLM prompts for repeated queries
- **Inputs**: Prompt hash
- **Outputs**: Cached response or cache miss
- **Behavior**: Hash prompt content, store responses, manage TTL

#### Feature: Memory Optimization
- **Description**: Optimize memory usage for large contexts
- **Inputs**: Context size, memory limit
- **Outputs**: Optimized context
- **Behavior**: Lazy load files, implement LRU eviction, paginate large files

## Module Definitions

### Module: cli/core/analyzer.py
- **Maps to capability**: Core Analysis Engine
- **Responsibility**: LLM-powered code structure analysis
- **Exports**:
  - `MiderAnalyzer` - Main analysis class
  - `analyze_file()` - Single file analysis
  - `analyze_batch()` - Multi-file analysis

### Module: cli/core/context_manager.py
- **Maps to capability**: Performance Optimization (caching), Core Analysis
- **Responsibility**: Build prompts, manage analysis cache
- **Exports**:
  - `PromptBuilder` - Dynamic prompt construction
  - `get_cached_analysis()` - Cache lookup
  - `invalidate_cache()` - Cache management

### Module: cli/core/session_manager.py (NEW)
- **Maps to capability**: Session Management
- **Responsibility**: Session state persistence and restoration
- **Exports**:
  - `SessionManager` - Session lifecycle management
  - `save_session()` - Persist to disk
  - `load_session()` - Restore from disk
  - `get_session_list()` - List available sessions

### Module: cli/coders/
- **Maps to capability**: Code Editing System
- **Responsibility**: Multi-strategy file editing
- **Exports**:
  - `CoderRegistry` - Strategy selection
  - `WholeFileCoder` - Full replacement
  - `EditBlockCoder` - Block editing

- **Maps to capability**: Interactive CLI Interface

- **Exports**:
  - `SwingUIComponents` → `MiderUIComponents` - UI widgets
  - `InteractiveUI` - REPL management

### Module: actions/file_editor.py
- **Maps to capability**: Code Editing System (Backup & Rollback)

## Critical Test Scenarios

### MiderAnalyzer
**Happy path**:
- Analyze valid C file → returns structured analysis
- Analyze valid SQL file → returns bind variables, joins

**Edge cases**:
- Empty file → returns minimal analysis
- Very large file (>10K lines) → handles without OOM
- Binary file → graceful rejection

**Error cases**:
- Invalid file path → FileNotFoundError with message
- LLM API timeout → retry with backoff

### SessionManager
**Happy path**:
- Save session → JSON file created
- Load session → state fully restored

**Edge cases**:
- Save with 50 files in context → completes in <5s
- Load corrupted file → graceful error

**Error cases**:
- Save to read-only path → permission error
- Load non-existent file → FileNotFoundError

### Code Editing
**Happy path**:
- WholeFile edit → file replaced, backup created
- EditBlock edit → block replaced, context preserved
- Rollback → original content restored

**Edge cases**:
- Edit file with no write permission → error before modification
- Concurrent edit attempts → handled safely

**Error cases**:
- Invalid diff format → parse error with location
- Block not found → clear error message

## Test Generation Guidelines

1. Use pytest fixtures for file manager, session state
2. Mock LLM service for deterministic tests
3. Use pytest-cov for coverage reporting
4. Integration tests use tests/fixtures/ sample files
5. Performance tests measure actual timing, not mocks

## Technical Risks

**Risk**: LLM API rate limits during heavy usage
- **Impact**: High - blocks user workflow
- **Likelihood**: Medium
- **Mitigation**: Implement request queuing, aggressive caching
- **Fallback**: Graceful degradation with cached results

**Risk**: Memory exhaustion with large file contexts
- **Impact**: High - crashes CLI
- **Likelihood**: Medium
- **Mitigation**: Lazy loading, LRU cache eviction, file pagination
- **Fallback**: Warn user, limit context size

**Risk**: Branding refactor breaks imports
- **Impact**: Medium - requires debugging
- **Likelihood**: High
- **Mitigation**: Systematic search/replace, comprehensive import testing
- **Fallback**: Git revert to pre-refactor state

## Dependency Risks

**Risk**: OpenAI API changes
- **Impact**: Medium - requires code updates
- **Mitigation**: Abstract LLM interface, version pin

**Risk**: MCP server unavailability
- **Impact**: Low - MCP is optional feature
- **Mitigation**: Graceful fallback when MCP unavailable

## Scope Risks

**Risk**: Feature creep during refactoring
- **Impact**: Medium - delays delivery
- **Mitigation**: Strict phase boundaries, weekly reviews
- **Fallback**: Defer non-critical features

**Risk**: Underestimated test coverage effort
- **Impact**: Medium - delays Phase 2
- **Mitigation**: Start with critical paths, expand iteratively
- **Fallback**: Accept 60% coverage initially
