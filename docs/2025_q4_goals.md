### **Epic: 2025년 4분기 (11월-12월) 개발 목표**

**개요:** Swing CLI의 핵심 기능인 분석, 계획, 사용자 경험을 고도화하여 P1 기능의 기반을 완성합니다. 총 예상 소요 기간은 9주입니다.

---

### **1. [P0] CoeAnalyzer 캐싱 시스템 구현**

*   **개요:** Ask 모드에서 사용자가 구조 분석 요청 시에만 CoeAnalyzer를 실행하고 결과를 캐싱하여, `/add` 속도를 높이고 반복적인 분석 비용을 줄입니다.
*   **예상 소요 기간:** 1주
*   **관련 문서:** `docs/features_spec.md` - "CoeAnalyzer 캐싱 시스템 구현" 섹션

*   **세부 구현 계획:**
    1.  **[설계]** `context_manager.py`의 `PromptBuilder` 내에 파일 경로를 key로 사용하는 캐시(`_coe_analysis_cache`) 구조를 설계합니다.
    2.  **[기능]** `interactive.py`에 '구조 분석', '분석해줘' 등 키워드를 감지하는 `detect_structure_analysis_request` 함수를 구현합니다.
    3.  **[핵심]** `main.py`의 Ask 모드 로직에서 키워드가 감지되면, `Context Manager`를 통해 캐시를 확인하고 필요 시에만 `CoeAnalyzer`를 실행하도록 처리 흐름을 구현합니다.
    4.  **[통합]** `Context Manager`의 `build()` 메서드에서 캐시된 분석 결과가 있을 경우, 이를 시스템 프롬프트에 포함하여 LLM 호출의 정확도를 높입니다.
    5.  **[검증]** `/add` 명령어 수행 시 CoeAnalyzer가 실행되지 않아 속도가 빠른지 확인하고, Ask 모드에서 분석이 정상적으로 트리거되는지 검증합니다.
    6.  **[유틸]** 캐시 상태를 확인할 수 있는 디버그 명령어(예: `/coe-cache status`)를 추가합니다.

### **2. [P0] 공통 MD 파일 생성 기능 개발**

*   **개요:** `coe init`를 통해, 협업에 필요한 표준 마크다운 문서(예: `AGENTS.md`)를 자동으로 생성하는 기능을 개발합니다.
*   **예상 소요 기간:** 2주
*   **관련 문서:** `docs/features_sepc_roadmap.md` - "AGENTS.md 자동 생성" 섹션

*   **세부 구현 계획:**
    1.  **[설계]** 생성할 문서 종류(AGENTS.md 등)와 각 문서의 기본 템플릿을 정의합니다. 템플릿은 `templates/` 디렉터리에서 관리합니다.
    2.  **[명령어]** `coe init` 시 문서 생성을 트리거하는 로직을 구현합니다.
    3.  **[템플릿 엔진]** 템플릿 내용을 읽어와 실제 프로젝트에 맞는 내용(예: 프로젝트 이름)으로 일부 변수를 치환하는 기능을 구현합니다.
    4.  **[파일 생성]** 정의된 템플릿을 바탕으로 실제 `.md` 파일을 작업 디렉터리에 생성하는 `FileManager` 연관 기능을 개발합니다.

### **3. [P1] 튜토리얼 모드 구현**

*   **개요:** 신규 사용자가 CLI의 핵심 기능을 쉽게 익힐 수 있도록, 실제 Fixture 파일을 사용하여 주요 기능(분석, 질문, 편집)을 체험하는 대화형 튜토리얼을 개발합니다.
*   **예상 소요 기간:** 2주
*   **관련 문서:** `docs/features_spec.md` - "튜토리얼 모드 (개발 예정)" 섹션

*   **세부 구현 계획:**
    1.  **[시나리오]** `features_spec.md`에 명시된 튜토리얼 5단계(파일 추가 → C 분석 → XML 분석 → SQL 분석 → 질문/편집) 흐름을 구체화합니다.
    2.  **[UI/UX]** `prompt_toolkit`을 사용하여, 사용자가 Enter 키를 눌러 각 단계를 진행하고 설명을 볼 수 있는 대화형 인터페이스를 구현합니다.
    3.  **[명령어]** `/tutorial` 명령어를 통해 튜토리얼 모드를 시작하는 진입점을 만듭니다.
    4.  **[통합]** 튜토리얼 각 단계에서 `/add`, `/ask` 등 기존 CLI 명령어들을 내부적으로 호출하여 실제 기능처럼 동작하게 합니다.
    5.  **[Fixture]** `tests/fixtures/`에 있는 실제 C, XML, SQL 파일을 튜토리얼 실습용으로 사용하도록 경로를 설정합니다.

### **4. [P1] AI Task Orchestration 개발**

*   **개요:** "Text-to-SQL"과 같은 복잡한 자연어 요청을 LLM이 스스로 단계별 실행 계획으로 분해하고, 사용자의 승인을 받아 각 단계를 순차적으로 실행하는 'Architect 모드'의 핵심 엔진을 개발합니다.
*   **예상 소요 기간:** 4주
*   **관련 문서:** `docs/features_sepc_roadmap.md` - "Architect 모드" 섹션

*   **세부 구현 계획:**
    1.  **[1단계: Plan 생성]**
        *   사용자의 자연어 요청(예: "유저별 구매내역 조회 API 만들어줘")을 받아, LLM이 JSON 형식의 실행 계획(Plan)을 생성하도록 프롬프트를 설계합니다.
        *   계획에는 `/edit`, `/exec`, `/test` 등 필요한 명령어와 파라미터가 포함되어야 합니다.
    2.  **[2단계: Plan 시각화 및 승인]**
        *   생성된 실행 계획을 사용자에게 Rich 테이블 또는 트리 형태로 명확하게 보여줍니다.
        *   사용자가 전체 계획 또는 각 단계를 실행할지 승인/거부할 수 있는 인터페이스를 구현합니다.
    3.  **[3단계: 순차적 실행 엔진]**
        *   승인된 계획에 따라 각 단계를 하나씩 실행하는 오케스트레이션 로직을 구현합니다.
        *   각 단계의 실행 결과(성공/실패)를 기록하고, 실패 시 중단하거나 사용자에게 다음 행동(수정/건너뛰기)을 묻는 로직을 포함합니다.
    4.  **[4단계: 상태 저장]**
        *   전체 실행 과정과 결과를 `plan.yaml` 같은 파일에 저장하여 추적 가능하게 합니다.
    5.  **[명령어]** `/architect` 명령어를 통해 AI Task Orchestration 기능을 시작하는 진입점을 구현합니다.
